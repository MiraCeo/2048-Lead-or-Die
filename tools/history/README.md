# tools/history —— 一次性变更脚本（已执行完）

这些脚本是**变更历史**，不是流水线的一部分。请不要在构建或测试里引用它们。

它们的价值在于：每个脚本记录了那一次改动的**精确替换文本、锚点与理由**，
是“为什么这么改”的一手证据。改动溯源时按文件名里的序号（step1…step16）顺序读即可。

| 前缀 | 内容 |
| --- | --- |
| `step1…step16` | 功能与界面改动（含配套的测试同步脚本 `*b_tests` / `*c`） |
| `doc_sync*` / `doc_chinese` / `doc_finish` | 项目文档的历次更新 |
| `handover_doc*` | 交接文档的状态对照与执行前必读 |
| `phase1_deroot.py` | 阶段 1「路径去绝对化」：把写死的 `D:\2048` 换成从仓库结构推导 |

### 关于 `phase1_deroot.py`

它执行的是**「时代分界线」式**的改动：改造前所有脚本都假设仓库在 `D:\2048`，
改造后一律从 `tools/_root.py` 推导。所以把它重新跑一遍**不会**再命中锚点
（全部报"命中 0"），这是正常的 —— 那时的绝对路径已经不存在了。

它的价值是记录了两种形态的**精确差别**，供排查同类问题时参考：
Python raw 串里路径是 **1 个反斜杠**，JS 普通串里是 **2 个**，
而**仓库目录名那一段（`2048`）要丢掉** —— 路径由 `ROOT` 表达，不能再列一遍。
（这个过程连错了四轮，全部栽在转义层级上，最后改成手写字符解析器才做对。）

当前工具链、测试与诊断脚本在上一级 `tools/` 目录。完整说明见 项目文档.md §14.3 / §14.4。
